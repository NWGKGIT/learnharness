# Desktop builds and releases

The fork currently releases Linux x64 packages: AppImage, Debian (`.deb`), RPM (`.rpm`), and an Arch/pacman package (`.pacman`). The Arch package is generated by electron-builder's pacman target and can be installed with `pacman -U`. The GitHub update feed points to `NWGKGIT/learnharness`.

## Release workflow

[Linux desktop release](../.github/workflows/release.yml) runs quality gates, builds all four packages on Ubuntu, and checks the packaged provider and demo runtimes. It validates the Linux updater feed against the built files and creates `SHA256SUMS`.

- A manual workflow dispatch is a rehearsal: packages, updater metadata, and checksums are retained as workflow artifacts for seven days. It does not create a GitHub release.
- Pushing a `vMAJOR.MINOR.PATCH` tag matching the version in `package.json` runs the same checks and publishes a GitHub release automatically. The tag must already exist; an existing release is not overwritten. A failed check prevents publication.

To release, update the version in `package.json` and `package-lock.json`, commit it, and push the matching tag. The repository must permit the workflow's `GITHUB_TOKEN` to write contents. No personal token or signing secret is required. Linux packages are unsigned.

## Local Linux build

Use Node 26 on Linux x64 and install RPM packaging tools. Run `npm ci` and `npm run plugins:setup`, then:

```sh
npm run build
node scripts/smoke-provider-runtime.mjs
node scripts/build-server.mjs
node scripts/smoke-server.mjs --electron
npx electron-builder --linux AppImage deb rpm pacman --x64 --publish never
node scripts/verify-linux-release.mjs dist
```

The workflow also runs native renderer tests and exercises the packaged application under Xvfb. See [Getting started](getting-started.md) for normal installation and use.
